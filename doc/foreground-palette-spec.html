FLOATCLOCK / FEATURE SPEC / 2026-10-09

中国色前景色与随机换色

随应用打包完整色库，每次启动生成 7 项前景色菜单，双击从色库抽取颜色并同步菜单选择。

已实现 · 自动化与发布混淆验证通过 · 跨平台实机验收待完成

1. 范围与关键约定

“完整色库”指 colors.json 中全部有效颜色；“菜单清单”指本次运行展示的 7 项。“从这个颜色清单随机一种”解释为从完整色库抽取，这样才会出现新颜色不在菜单清单中、需要替换当前项的情况。

已按此实现资源加载、前景色菜单及随机换色。背景色、描边、字体、拖动及双击判定方式保持现有行为。

2. 资源契约

来源：中国色 colors.json。原始文件已下载至 src/desktopMain/resources/colors.json，通过 classpath 随应用打包；运行时无需联网，每个进程只读取一次。

  • 快照日期：2026-10-09。526 条记录，按 hex 解析后有 526 个互不重复的颜色；name 非空，hex 均为合法六位十六进制值。
  • 源数据含 name、hex、RGB、CMYK、pinyin。运行时只依赖 name 和 hex，忽略其他字段。hex 是唯一色值来源，解析为不透明的 24 位 RGB。
  • 以 RGB 判断颜色相等，不以名称或 hex 大小写判断。遇到重复 RGB 保留第一条；过滤空名称或非法 hex，记录汇总告警。
  • 源文件保持原样。更新色库时替换资源并重新发布，不增加在线刷新功能。
数据差异：8 条记录的 RGB 数组与 hex 不一致：杏仁黄、藤黄、杏黄、淡灰绿、米色、金黄、玫瑰灰、月季红。统一使用 hex，避免同一颜色在不同入口显示不同结果。

3. 启动时生成菜单

  1. 等待 ClockSettings.ready，使用恢复完成的当前 RGB 初始化一次。Compose 重组、重新打开菜单及显示器热插拔不重新抽样。
  2. 当前色放第一项并选中；从完整色库排除相同 RGB 后，无放回随机抽取 6 项，按抽取顺序追加。正常情况下恰好 7 项，互不重复。
  3. 旧配置颜色若在色库中，显示其中文名；若不在，显示“自定义色 #RRGGBB”，仍占一个名额，再抽取 6 项。
  4. 现有 ThemeModel 始终含 RGB，没有“是否主动选过”标记。全新安装保留默认 #1A3B32（深海绿）作为当前选择，再抽取 6 项；初始化不主动改色，不为此新增持久化字段。

使用 JRadioButtonMenuItem + ButtonGroup 表示互斥选择，始终只有一项选中。条目显示中文名称，tooltip 显示 #RRGGBB；库外颜色直接在名称中展示色值。保留末尾分隔线及“随机”命令，命令不计入 7 项。

前景色 ▸
    ✓ 深海绿
      … 本次随机抽取的另外 6 项 …
    ──────────
      随机

点击条目后即时应用其 RGB、切换选中态并保存，不重新抽样或排序。点击已选项不额外写入。设置就绪且菜单完成初始化前，前景色菜单禁用，双击换色不执行。

4. 双击与“随机”

两种入口共用一个动作，从完整色库中排除当前 RGB 后等概率抽取一种。候选存在时保证颜色发生变化；不再使用 HSB 生成、亮度／饱和度约束或色相距离筛选。

结果菜单变化设置变化
新颜色已在菜单中选中对应条目；所有内容及顺序不变应用并保存新 RGB
新颜色不在菜单中原位替换当前选中槽位的 RGB、名称、tooltip，并保持该槽位选中；其余 6 项不变应用并保存新 RGB
无其他可选颜色随机命令禁用；双击无操作不写入
[A, B✓, C, D, E, F, G]
随机到 C → [A, B, C✓, D, E, F, G]
再随机到 H → [A, B, H✓, D, E, F, G]

不追加第 8 项，不替换未选中的槽位；菜单外新颜色取代旧选中色后，旧色仍可由完整色库再次抽到。

5. 状态与持久化

  • 会话级共享有序菜单列表和选择状态，各显示器使用同一个前景 RGB；时钟与网速文字同步更新。
  • 继续保存 ThemeModel.colorR/colorG/colorB，通过 ClockSettings.update 更新。菜单内容、顺序及名称不持久化。重启保留最终颜色，再抽取另外 6 项。
  • 随机只在用户动作触发时执行一次，先确定目标 RGB，再提交纯设置变换；不能在可能被重放的 update transform 内随机抽样。
  • 菜单从 settings.model 的有效 RGB 同步：存在则选中对应条目，不存在则替换当前选中槽位。这一规则同时用于保存失败回退，保证回退后实际颜色存在且被唯一选中。
  • 沿用 ClockSettings 的串行保存和待处理操作重放。失败后若还有后续操作，以重放后的有效颜色为准；不要求恢复失败前整份菜单内容。
  • Swing 条目、选中态、tooltip 与 ButtonGroup 更新均在 EDT 执行。监听器读取槽位最新 RGB，避免替换条目后仍应用旧颜色。

6. 异常与降级

可用颜色不足时保留当前颜色，再加入所有可用且不同的颜色，允许少于 7 项，不补造预设。资源缺失、JSON 损坏或无有效条目时仅保留当前色，禁用随机，时钟继续运行。正常资源必须通过完整性验证并满足 7 项要求。

资源读取异常及降级使用 SLF4J WARN，固定简单名称 logger，例如 LoggerFactory.getLogger("ForegroundPalette")；用 {} 传参，异常对象放最后。设置保存失败沿用 ClockSettings 的 ERROR。高频绘制不重复读取资源或输出正常状态日志。
