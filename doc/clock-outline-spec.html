FLOATCLOCK / FEATURE SPEC / 01

时钟文字描边

为时钟文字增加黑色或白色轮廓。开启时背景固定透明，保留前景色，让文字在桌面内容上更清晰。

日期：2026-09-28 · 状态：已实现，跨平台实机验收待完成 · 基于当前 Compose Multiplatform 1.8.2 桌面实现

01 / 功能边界与默认决策

用户明确需求：在“时钟样式”中增加“显示描边”复选框；开启后背景固定透明；增加“描边颜色”，仅可选黑色和白色。

本 spec 的补充设计决策：默认关闭描边，默认描边色为白色；描边同时作用于时间和已显示的网速；关闭描边后恢复此前背景色。描边宽度作为内部常量，不增加设置项。

“描边”指字形轮廓，不是悬浮窗矩形边框，也不是空心文字。数码管样式、普通样式及字体回退均支持。文字内部仍使用现有前景色，随机换色和双击换色继续只改变前景色。

沿用现有 Swing 右键菜单，“显示描边”放入“时钟样式”；“描边颜色”作为一级菜单，与“前景色”“背景色”并列，位于“背景色”之后。

  • 显示描边：使用 JCheckBoxMenuItem，点击立即生效并持久化；不切换数码管／普通样式。
  • 描边颜色：子菜单用互斥单选项（JRadioButtonMenuItem + ButtonGroup）；始终只有黑、白之一被选中。关闭描边时该子菜单禁用，保留上次选择。
  • 背景色：开启描边时整组禁用，标签改为“背景色（描边时固定透明）”，选中态显示透明；关闭时恢复“背景色”标签、可选状态及之前的选择。
  • 即时一致：所有显示器上的悬浮窗与菜单同步更新，不重新创建窗口，不改变置顶、拖动、右键及双击行为。

03 / 绘制方案

结论：同一份文字布局，先 Stroke，再 Fill

新增可复用 OutlinedClockText，使用 Compose 的 TextMeasurer 生成一份 TextLayoutResult，两次 drawText 共享布局与坐标。第一次绘制描边，第二次绘制实心前景色。这样字体回退、字距、基线和上下行中的箭头都由同一套排版处理。

已核对本机缓存的 ui-text-desktop 1.8.2 源码：drawText(textLayoutResult, color, …, drawStyle) 支持 DrawStyle，并传递到底层段落绘制；因此方案无需升级 Compose、引入新依赖或增加 JNI。公共 API 说明参见 Compose Text API。已通过本项目的 Compose 离屏渲染测试，覆盖普通／数码管字体、黑白描边及 100%／125%／150%／200% 缩放；原生窗口的跨平台交互仍需实机验收。

候选方案判断原因
同一 TextLayoutResult 双遍绘制采用排版完全一致，轮廓连续，可直接控制线宽与圆角连接。
两个 Text 叠加不作为主方案需要协调重复布局、语义、尺寸和更新；容易出现两层不同步。
多个偏移文本／阴影不采用模拟轮廓的方向性明显，小字号容易糊，增加绘制次数。
AWT／Skia 字形路径或位图膨胀不采用需额外处理字体回退、字形排版或离屏资源；维护成本高于现有 Compose API。

线宽与层叠

  • 时间仍为 48.sp，可见外轮廓目标 1.dp；Stroke 总宽为 2.dp。
  • 网速仍为 14.sp，可见外轮廓目标 0.5.dp；Stroke 总宽为 1.dp。
  • Stroke 沿字形边缘居中，后绘的 Fill 覆盖内部半宽；使用 StrokeJoin.Round 避免尖角外突。
  • 描边使用完全不透明的纯黑或纯白；填充使用原前景色。允许填充与描边同色，不自动换色。
  • 线宽按当前窗口 density 换算为像素，不使用固定物理像素。常量可在实现后的视觉验收中微调，并同步更新本 spec。
// 绘制核心示意；不是完整可编译组件。
// layout、origin、边距均在测量阶段确定，两遍共用。
if (showOutline) {
    drawText(
        textLayoutResult = layout,
        color = outlineColor,
        topLeft = origin,
        drawStyle = Stroke(
            width = 2f * outlineOutsideWidth.toPx(),
            join = StrokeJoin.Round,
        ),
    )
}
drawText(layout, color = foregroundColor, topLeft = origin, drawStyle = Fill)

布局、防裁切与缓存

  1. 以原 Text 的有效 TextStyle 为基准，保持 fontFamily、fontSize、行高、字重和字距；不要使用一套未经对齐的默认 Canvas 字体样式。
  2. 使用单行、不折行和 TextOverflow.Visible 测量，预留真实文字宽度，不能被当前窗口的旧宽度约束后再反推窗口尺寸。1.8.2 的 drawText 会在溢出且 overflow 非 Visible 时裁切，需要显式规避。
  3. 每个文本组件四周增加 ceil(外轮廓像素宽 + 1.dp.toPx()) 的透明安全区；描边关闭时不增加。组件尺寸为布局尺寸加两侧安全区，绘制原点向内平移相同值。保留外层 10.dp／6.dp 边距与原行间距。
  4. 为自绘组件保留文本语义，时间和网速各仅一份；如父布局依赖基线，则按安全区偏移后的文字基线暴露 alignment line。
  5. 缓存键包含文字、有效字体样式、字体解析器、density、fontScale、布局方向及测量约束。颜色只影响绘制；时间字符串未变时不重复测量。网速仍按现有频率更新，不引入动画或逐帧刷新。
现有窗口尺寸逻辑必须一并调整。当前 OverlayWindow 的 sizeSettled 仅在样式／网速显示开关变化时重置，无法可靠容纳描边边距与后续变宽的网速。应使用独立于当前窗口尺寸的自然内容测量，每次自然尺寸实际变化才更新窗口；防止旧窗口约束导致测量锁死。

尺寸策略：字体、显示网速、描边开关或 density/fontScale 改变时，重建本轮尺寸基准；同一配置内用已见自然宽高的最大值，只在需要时扩展，避免每秒收缩／扩展。关闭网速或描边后允许收回空间。现有自动定位规则保持；文字更新但尺寸未变时，不调用 setSize 或重定位。首帧不能将受初始窗口约束的尺寸锁定为最终值。

04 / 状态与持久化

// 在 ThemeModel 末尾增加，兼容旧 JSON。
val showOutline: Boolean = false,
val outlineColor: String = "white",

// backgroundColor 保存用户偏好，最终绘制色集中派生。
effectiveBackground = if (showOutline) Transparent else resolvedBackground
resolvedOutline = if (outlineColor in setOf("black", "white")) outlineColor else "white"
  • 通过 ClockSettings.update 提交 copy 变更，由 ThemeDataStore.update 使用 DataStore.updateData 串行保存；菜单颜色入口仅来自固定黑白取值表。
  • 不覆盖 backgroundColor 来实现透明；有效背景与菜单选中态均从同一份归一化状态派生，避免启用瞬间出现实色背景。
  • 缺失字段取默认值；未知描边颜色读作 white，不造成启动失败。JSON 损坏或字段类型错误仍按既有异常策略处理，不扩大本次配置修复范围。
  • 菜单发送目标值而不是盲目取反。连续设置按用户操作顺序串行落盘；乐观状态要带版本控制，防止较旧 DataStore 发射覆盖最新操作。失败时回到最后已确认配置，同步菜单和所有窗口。
  • Swing 菜单的 selected、enabled、text 更新在 EDT 执行；不要把 remember 创建菜单时的旧布尔值捕获成永久状态。
  • 写入失败按项目规范记录 ERROR，并将异常放在最后一个参数；绘制和高频刷新不输出 INFO 日志。

06 / 验收标准

ID场景通过标准
A1无新字段的旧配置样式、前景、背景、网速设置不变；描边默认关闭。
A2从透明／黑／白背景开启与关闭开启统一透明且背景禁用；关闭准确恢复原选择。
A3黑白描边切换、关闭再开、重启即时同步并持久化；互斥选择始终正确。
A4普通／数码管／digital-7 缺失回退字形内有原色填充，外轮廓连续；两遍无错位、无空心。
A5时间 00:00、11:11、23:59；网速箭头及 B/s、KB/s、MB/s 文本数字、冒号、箭头、大小写单位均完整，小字内部空隙不被明显堵塞。
A6浅色、深色和复杂桌面背景合适描边色下可辨认；透明区域不出现矩形底色、阴影或棋盘格。
A7100%、125%、150%、200% 缩放与跨屏／热插拔适用平台上粗细随 density 一致；顶部、底部和两端无裁切。
A8网速由短变长，开关描边／网速／样式窗口能扩展并在配置变化后重新收敛；同一配置内不每秒来回缩放。
A9多屏、快速连续操作、模拟写入失败最后一次操作获胜；所有窗口和菜单一致；失败回退且保留异常日志。
A10关闭描边与原版比较；拖动、双击、右键、置顶关闭时排版视觉等价；原交互有效，没有重复文本语义。

自动化验证：针对旧 JSON 默认值、未知颜色归一化、背景状态转换、持久化往返和自然尺寸增长增加有行为价值的测试。绘制使用透明离屏图像检查外轮廓存在、内部填充色不变及透明安全区无越界；跨平台抗锯齿采用容差，不要求逐像素完全一致。

实机验证：完成桌面编译后，在 macOS、Windows、Linux 可用环境执行对应检查；无法覆盖的平台明确标为待验证。重点先验证 digital-7 的 48.sp 描边和 14.sp 网速，不以 HTML 示意代替实机截图。

07 / 风险与交付顺序

  1. 先验证渲染：在现有依赖上完成最小双遍绘制样例，检查数码管细缝、箭头回退与高 DPI；若不通过，先定位测量、裁切或字体问题，再重新评审方案。
  2. 再接状态与菜单：完成持久化和有效背景派生，再接入两个文本组件及全部窗口。
  3. 最后验证尺寸和交互：修正自然尺寸测量、运行兼容与回归矩阵。未完成视觉验收前，线宽仅为设计初值。

本期不增加自定义描边色、线宽滑块、发光、阴影或系统自动配色；这些不属于当前需求。
